# HotChocolate GraphQL in the Kommunal-App backend (.NET 8)

## Where things live

HotChocolate **13.9.16**. The whole GraphQL server is one fluent chain in `Program.cs`. Feature-based: resolvers in `Features/<Domain>/Queries/*.cs` and `Mutations/*.cs`; entities exposed as GraphQL types in `Features/<Domain>/<Entity>.cs`.

> For **how resolvers obtain a `DomainContext`, DataLoaders, offset paging over `IQueryable`, NodaTime `Instant`** → **ef-core** skill. For **stitching / consuming Payload CMS** → **graphql-stitching** skill. This skill is the GraphQL-server layer on top.

## Core principles

1. **Types are discovered by attributes, registered by a source-generated module.** `.AddAPITypes()` (`Program.cs`) is generated by `HotChocolate.Types.Analyzers` from the assembly name (`API` → `AddAPITypes`). You never call `.AddType<...>` for your resolvers and there's no `[Module]` marker — annotate the class and it's picked up.
2. **One attribute per role:**
   - `[QueryType]` / `[MutationType]` on a class → its public methods become root query/mutation fields.
   - `[ExtendObjectType<T>]` → add computed/related fields to type `T`; the method takes `[Parent] T`.
   - `[ObjectType]` on an entity class → expose that EF entity as a GraphQL object type (TPH leaves, entities needing explicit typing).
3. **Cross-cutting services inject as plain parameters** (no `[Service]`) because they're registered with `.RegisterService<T>()` (`Program.cs`): `CurrentUserAccessor`, `IClock`, `WalkerFactory`, and `DomainContext`. `[Service]` is still used for anything not registered that way.
4. **Signal business errors by throwing a `DomainException` subclass.** With `[Error(typeof(...))]` + `AddMutationConventions()` the throw becomes a typed member of the mutation's `errors` union, not a top-level error.
5. **Every schema change must be re-exported** (`dotnet run -- export-schema-only`) or the frontends drift and CI fails.

## Patterns

### Root query / mutation
```csharp
[QueryType]
public class HinweisQueries {
    [UseOffsetPaging(IncludeTotalCount = true, MaxPageSize = 100)]
    [UseFiltering]
    [Authorize]
    public IQueryable<Hinweis> GetHinweise(Guid kommuneId, DomainContext db) =>
        db.Hinweise.Where(h => h.KommuneId == kommuneId && !h.MarkedForDelete);
}
```
Return `IQueryable<T>`; the paging/filtering middleware composes it. Paging is offset-based; `[UseProjection]`/`[UseSorting]`/cursor `[UsePaging]` are not used here (see ef-core).

### Computed / related fields on a type
```csharp
[ExtendObjectType<Kommune>]
public class KommuneExtensions {
    public bool AbfallkalenderEnabled([Parent] Kommune kommune) => ...;
    public async Task<EncryptedValue?> PrivateKey([Parent] Kommune kommune, CurrentUserAccessor user) { ... }
}
```

### Typed mutation errors
Declare a `DomainException` subclass, `throw` it, list it with `[Error]`:
```csharp
public class UntereinheitNotFoundException : DomainException {
    public UntereinheitNotFoundException() : base("Untereinheit not found") { }
}

[MutationType]
public class UntereinheitMutations {
    [Error(typeof(NotAllowedException))]
    [Error(typeof(UntereinheitNotFoundException))]
    public async Task<Untereinheit> UntereinheitUpdate(
        DomainContext db, CurrentUserAccessor currentUserAccessor, Guid untereinheitId, ...) {
        var (user, _) = await currentUserAccessor.EnsureBackofficeUser(BackofficeNutzerArt.Superadmin);
        var u = await db.Untereinheit.AsTracking().FirstOrDefaultAsync(x => x.Id == untereinheitId)
                ?? throw new UntereinheitNotFoundException();
        ...
    }
}
```
- `AddMutationConventions()` (`Program.cs`) generates `XxxPayload { xxx, errors }`.
- `GraphQLErrorFilter` (`Infrastructure/GraphQLErrorFilter.cs`) maps any uncaught `DomainException` → `{ code, message }`, and everything else → Sentry + code `UNKNOWN` (message hidden in release, shown in DEBUG). `CurrentUserAccessor.Unauthenticated` and `NotAllowedException` are not sent to Sentry.
- **Error codes are derived from the class name:** `ErrorCodeType.ExceptionTypeNameToGraphQLCode` strips `Exception`, underscores, uppercases → `NotAllowedException` → `NOT_ALLOWED`. They're exposed as the `ErrorCodeType` GraphQL enum (`Infrastructure/ErrorCodeType.cs`, auto-built from every `DomainException` subclass). **Renaming an exception is a breaking client change.**

### Authorization
```csharp
[Authorize]   // requires a valid JWT — no roles/policies exist
public async Task<...> Foo(CurrentUserAccessor currentUserAccessor) {
    var (backofficeUser, helpers) =
        await currentUserAccessor.EnsureBackofficeUser(BackofficeNutzerArt.Superadmin);
    // throws NotAllowedException if the user is deleted, the wrong art, or lacks the Funktionsberechtigung
}
```
- `[Authorize]` (wired at `Program.cs`) only checks authentication. **Real authorization is imperative** via `CurrentUserAccessor` (`Features/Auth/CurrentUserAccessor.cs`) — it reads the user from the JWT (`IHttpContextAccessor`) and loads it via `IUserByIdDataLoader`.
- Fine-grained permissions are `[Funktionsberechtigung]`-decorated enums, checked through `EnsureBackofficeUser` / `FunktionsberechtigungenService`.

### Custom scalars

| GraphQL scalar | Backing type | Registration (`Program.cs`) |
|---|---|---|
| `Instant` | `InstantType` (NodaTime **package**, not custom) | `.AddType<InstantType>()` (`:226`) |
| `StringExpression` / `BoolExpression` / `IntExpression` | custom `ScalarType<T, StringValueNode>` in `Features/Expressions/ScalarTypes.cs` | `.BindRuntimeType<StringExpression, StringExpressionType>()` (`:227-229`) |
| `ErrorCodeType` (enum) | auto-built from `DomainException` subclasses | `.AddType<ErrorCodeType>()` (`:225`) |
| Payload `JSONObject` / `EmailAddress` | `AnyType` | `AddPayloadCmsTypes()` (`:223`) |

`Guid`→`UUID` and `decimal`→`Decimal` use HotChocolate defaults (no custom binding). `EncryptedValue` is a plain object type (3 string fields), **not** a scalar; hide sensitive backing columns with `[GraphQLIgnore]`.

### Re-export the schema after any change
`dotnet run -- export-schema-only` runs `WriteSchemaToFrontends` (`Infrastructure/WriteSchemaToFrontends.cs`), which writes the Default schema SDL to **three** files:
- `web/bereich-a/schema.graphql`
- `web/stele/schema.graphql`
- `app/lib/graphql/schema.graphql`

Then run each consumer's codegen (bereich-a / stele `pnpm graphql`, app `task app:gen`). `RemoveUnreachableTypes = true` (`Program.cs`) keeps the ~25k-line stitched BereichB schema out of the export.

### Test a GraphQL operation
Integration tests execute against the **real** schema via `WebApplicationFactory<API.Program>` + `IRequestExecutorResolver` (`UnitTests/AppIntegrationTests.cs`; `API.Program` is `partial` for this at `Program.cs`):
```csharp
var executor = await Factory.Services.GetRequiredService<IRequestExecutorResolver>()
    .GetRequestExecutorAsync();
var request = QueryRequestBuilder.New().SetQuery(query).SetVariableValue("input", input);
if (user != null) { SetHttpContextUser(user); request.SetUser(user); } // CurrentUserAccessor reads HttpContext.User
var result = await executor.ExecuteAsync(request.Create());
```
Snapshots via `queryResult.ToJson().MatchSnapshot()` (Snapshooter). Real Postgres, no InMemory (see ef-core).

## Anti-patterns

- ❌ Manually `.AddType<MyQueries>()` or adding a `[Module]` marker — `AddAPITypes()` source-gen discovers `[QueryType]`/`[MutationType]`/`[ExtendObjectType<T>]`/`[ObjectType]`. If a field is missing from the schema, check the **attribute**, not the registration.
- ❌ `throw new Exception(...)` (or any non-`DomainException`) for a business error → surfaces as `UNKNOWN` with the message hidden in release. Throw a `DomainException` subclass and list it with `[Error]`.
- ❌ Renaming a `DomainException` subclass casually — the client-visible error `code` is derived from its name (breaking change).
- ❌ `[Authorize(Roles = ...)]` / policies — none exist; do role/permission checks imperatively via `CurrentUserAccessor.EnsureBackofficeUser(...)`.
- ❌ `DateTime` / `DateTime.UtcNow` — use `Instant` + injected `IClock` (see ef-core).
- ❌ Forgetting `dotnet run -- export-schema-only` after a schema-affecting change → CI schema-drift failure + stale frontend types.
